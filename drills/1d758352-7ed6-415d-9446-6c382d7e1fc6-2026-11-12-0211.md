## Draf final (sesudah wrapper)

**EIP-1167 minimal-proxy clones vs. full standalone contracts for an ERC-20 vault fleet on L2**

---

### Gas cost

| Phase | Minimal proxy (EIP-1167) | Standalone |
|-------|--------------------------|------------|
| **Deploy factory** | ~450k–550k gas (one-time) | N/A |
| **Per-vault deploy** | ~45k–65k gas (clone + `initialize`) | ~1.2M–1.8M gas (full bytecode) |
| **Per-call overhead** | +300–500 gas (delegatecall) | baseline |
| **L2 calldata** | ~200–300 bytes smaller per deploy tx | larger deploy calldata |

**Verdict**: Clones win decisively on deploy gas when vault count > 5–10. On L2s where calldata dominates cost (Arbitrum, Optimism, Base), the savings compound. The per-call delegatecall overhead is negligible for vaults (infrequent admin ops, user calls hit implementation directly via delegatecall).

---

### Upgradeability

| Dimension | Minimal proxy | Standalone |
|-----------|---------------|------------|
| **Implementation upgrade** | Single factory `upgradeTo(address)` call updates all clones | Must redeploy each vault or use separate proxy pattern per vault |
| **Selective upgrade** | Requires beacon proxy (EIP-1822) or per-clone `upgradeTo` (defeats gas advantage) | Trivial — each is independent |
| **Storage layout risk** | **Critical**: All clones share implementation storage layout. A bad upgrade bricks *every* vault. | Isolated — bad upgrade affects one vault. |
| **Emergency pause** | One switch at implementation level | Must coordinate per vault or build shared pause module |

**Verdict**: Clones give cheap fleet-wide upgrades but create **correlated failure risk**. Standalone contracts localize blast radius. For high-value vaults holding diverse assets, standalone (or beacon proxy) is safer. For homogeneous, low-value, high-count vaults (e.g., 100+ strategy vaults with identical logic), clones are pragmatic.

---

### Auditability

| Aspect | Minimal proxy | Standalone |
|--------|---------------|------------|
| **Code review surface** | Audit implementation once + factory (tiny) | Audit each deployment or trust identical bytecode |
| **Verifier ergonomics** | Etherscan/Sourcify show proxy → implementation link; "Read/Write Contract" tabs work seamlessly | Each contract verified independently; more UI clutter |
| **Formal verification** | Verify implementation once; clones inherit proof | Must verify each or prove bytecode equivalence |
| **Supply-chain risk** | Factory deployer controls implementation pointer — single point of trust | No central pointer; each vault immutable unless self-upgradeable |

**Verdict**: Clones *reduce* audit effort for the logic, but *concentrate* trust in the factory admin key. Standalone contracts distribute trust but multiply review burden. Use clones only if factory upgrade mechanism is timelocked + multisig + audited.

---

### Decision matrix

| Scenario | Choose |
|----------|--------|
| >20 vaults, identical logic, low individual TVL, trusted multisig factory admin | **EIP-1167 clones** |
| <10 vaults, or vaults diverge in parameters/logic over time | **Standalone** |
| High TVL per vault, heterogeneous assets, regulatory need for isolation | **Standalone** (or beacon proxy) |
| Need fleet-wide emergency pause *and* selective upgrade | **Beacon proxy (EIP-1822)** — clone gas profile, per-vault upgrade control |
| L2 with very cheap calldata (zkSync, Starknet) and low deploy frequency | Standalone gap narrows; favor auditability |

---

### When the answer flips

1. **TVL concentration crosses threshold** — if one vault holds >5% of total fleet TVL, correlated upgrade risk outweighs deploy savings.
2. **Logic divergence** — if vaults need different fee structures, oracle configs, or access control, clones become a liability (you end up deploying multiple implementations anyway).
3. **Upgrade cadence drops** — if you upgrade quarterly not weekly, deploy gas amortization matters less; standalone clarity wins.
4. **L2 fee market shifts** — if calldata price spikes (e.g., L1 blob fee surge), clone deploy advantage grows; if L2 introduces native account abstraction making delegatecall cheaper, clone call overhead shrinks further.
5. **Audit budget fixed** — one deep audit of implementation + factory vs. N shallow audits: clones win on cost, but only if the single audit is *excellent*.

---

### Practical recommendation for a launch

**Start with a beacon proxy (EIP-1822)**. It gives:
- Clone-level deploy gas (~50k/vault)
- Per-vault upgrade control (no correlated bricking)
- Single implementation audit surface
- Clean verifier UX

Move to minimal clones only if vault count >100 *and* logic is frozen *and* factory admin is a battle-tested timelocked multisig. Move to standalone only if vaults must diverge or regulatory isolation is required.
