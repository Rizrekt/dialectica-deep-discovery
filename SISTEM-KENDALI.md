## Cara dokumen ini dipakai (mengikat)

1. Setiap perintah berdiri user untuk Dialectica adalah **klausul** di dokumen ini. Klausul hanya sah sebagai sistem kendali bila punya tiga hal: **(a) bunyi klausul + sumbernya**, **(b) mekanisme eksekusi yang bernama** (cron + butir / gerbang kode / langkah sesi), **(c) cara verifikasi kepatuhannya** (artefak/run-log pembukti).
2. **Status klausul:** `TERKAIT` = mekanisme ada + terbukti jalan dari run/artefak terakhir · `TERKAIT-BELUM-TERBUKTI` = mekanisme ada, bukti run belum ada · `CELAH` = tidak ada mekanisme — perintah cuma tercatat. Klausul CELAH tidak boleh dibiarkan: ia masuk DAFTAR PERBAIKAN di bawah.
3. **Setiap run** (slot-hunt, learning-watch, daily-readiness, day-close, weekly-revision) memeriksa pekerjaannya lawan dokumen ini. **Weekly-revision mengaudit kepatuhan klausul per klausul.** Perintah baru user masuk dokumen ini + terkait mekanisme **di giliran yang sama** dengan perintahnya diterima (langkah sesi utama/kolom — lihat klausul G1).
4. Dokumen ini TIDAK mengubah badan cron/jadwal/config/kode. Perubahan semacam itu hanya lewat DAFTAR PERBAIKAN → keputusan sesi utama.
5. Sumber klausul: `~/workspace/user/dialectica-operator-prompt.md` (paket berdiri butir 1–18, transfer T1–T9, Addendum T10–T17 — dirujuk sebagai "Paket b.N" / "T-N"), `~/AGENTS.md` (dirujuk "AGENTS"), baris Dialectica `~/MEMORY.md` (dirujuk "MEMORY"). Bunyi klausul memakai kata-kata inti perintah user, bukan parafrase bebas.
