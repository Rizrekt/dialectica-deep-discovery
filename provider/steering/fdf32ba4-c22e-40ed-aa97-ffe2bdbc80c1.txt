VERIFIED FACTS you may state (from audited, hands-on use of baw v1.12.0, npm package @binance/agentic-wallet):
- Install pattern: the skill is distributed via the skills ecosystem (`npx skills add binance/binance-skills-hub`); the CLI itself is the npm package @binance/agentic-wallet, command `baw`, and every command supports `--json` machine-readable output.
- Pairing: the agent generates a pairing/verification flow; the USER approves in the Binance app. A verification code's validity window is short (about 5 minutes). Sessions persist roughly 30 days.
- Multiple simultaneous sessions: the CLI honors the BINANCE_BAW_DIR environment variable, so two wallets can hold two independent sessions side by side (default ~/.baw plus a second directory) without re-pairing.
- Message signing: `baw sign-message` performs EIP-712 typed-data signing WITHOUT a separate user tap (top-level command); it signs messages, not transactions.
- Transactions: `baw contract-call` is two-phase — a preview call (chain id, from, to, value, inputData) returns a requestId and a simulation; execution uses only that requestId. The operator reads the preview like an adversary: value beyond gas, token transfers, approvals/allowance changes, authority changes, unexpected external calls, or risk flags all abort the transaction. Fresh approval per materially different transaction.
- Developer Mode: a user-side toggle in wallet settings with an expiry (data.devMode = {enabled, expiresAt} via `baw wallet settings --json`); when it lapses, signing flows that depend on it stop until the user re-enables it.
- Chain support is explicit per wallet (e.g., BSC chain 56 and Ethereum mainnet chain 1 verified in use; Base 8453 also); the CLI does NOT support every chain (no Sepolia/Elysium in the verified setup).
- Failure modes observed in production use: a session can silently drop (both wallets at once) and require re-pairing by user tap; a read command can hang while status commands still answer — operational runbooks must distinguish "wallet mismatch" from "endpoint hang" before acting.
